# 会话知识晋升规则

> **定位**：填补 TRAE memory 管线中 topics.md → project_memory.md 的晋升缺口。不新增智能体角色、不新增存储位置，复用现有三级管线（session_memory → topics.md → project_memory.md）。
> **触发**：用户说出"归档本次会话"（或语境明确时简称"归档"）时，当值 Agent 执行本规则；不自动触发。
> **来源**：2026-08-18 评审 LOPD 式"会话归档官"智能体提案后否决（与 TRAE 自动 memory 管线冗余，污染 RAG 索引），改为规则驱动。决策记录：`.trae/notes/implemented/process/2026-08-18-memory-promotion-rule.md`

## 一、执行流程（六步闭环）

| # | 步骤 | 动作 | 闸门 |
|---|------|------|------|
| 1 | 读取 | 读本次会话在 topics.md 的摘要条目；信息不足时回读 `session_memory_<id>.jsonl` 关键段落 | — |
| 2 | 四分类提取 | 教训 / 决策 / 参数命令 / 未闭合风险（定义见下） | — |
| 3 | 查重 | 每条候选先 Grep project_memory.md，已有同义条目则合并改写原条目，禁止追加副本 | RAG 卫生闸门 |
| 4 | 用户确认 | 拟写入清单展示给用户，等确认；被否决条目丢弃，不落地 | 真源保护闸门 |
| 5 | 写入 | 按下方映射表落盘 | — |
| 6 | 风险提醒 | 未闭合风险不自动写入，以清单形式提醒用户决定去向 | — |

### 四分类定义

- **教训（Lessons）**：踩坑结论、错误根因、被证伪的假设（"X 不行，因为 Y，应改用 Z"）
- **决策（Decisions）**：技术选型/架构取舍 + 理由（"选 A 不选 B，因为…"）
- **参数与命令（Params）**：验证过的配置值、修复命令、环境步骤，可直接复用执行
- **未闭合风险（Risks）**：待办、隐患、需人工跟进的事项

### 写入映射

| 分类 | 去向 |
|------|------|
| 教训 | `project_memory.md` → `## Lessons Learned` |
| 决策（硬约束性质） | `project_memory.md` → `## Hard Constraints` |
| 决策（工程约定性质） | `project_memory.md` → `## Engineering Conventions` |
| 用户级偏好（跨项目通用） | `user_profile.md`（不写入项目 memory） |
| 重大架构决策 | `.trae/notes/` 决策记录（四态流转），日常教训不进入 |
| 未闭合风险 | 不落盘，提醒用户 |

条目格式：带 `【YYYY-MM-DD】` 或 `【YYYY-MM-DD·主题】` 前缀，便于审计追溯。

## 二、RAG 卫生红线

1. 只写事实条目，禁止叙事流水账（"我们讨论了…"）
2. 优先追加到已有小节，不轻易新建小节
3. 单条 ≤2 行：结论 + 关键参数/路径
4. 条目失效时改写或删除原条目，禁止追加"更正："式补丁条目
5. 与既有条目语义重叠时必须合并，不得并存

## 三、边界（与现有体系不重叠）

- **topics.md / session_memory 自动管线**：只读，不干预
- **文档维护工程师智能体**：其职责是代码 ↔ 用户文档同步（README/docs/CHANGELOG，外部用户层），本规则是会话 ↔ memory 晋升（内部真源层），无交集
- **`.trae/notes/`**：仅重大架构决策进入，防止 notes 膨胀
