### 2026新增关注焦点

- **AI/LLM 安全风险首次纳入应用安全顶层考量**
- **供应链安全上升为一级风险类别**，SBOM 成为标配
- **零信任架构常态化**，东西向流量微隔离引入审计要求
- **数据安全独立考核**（GA/T 2380-2026 等保新规）

### 十大漏洞详解

#### A01 — 失效的访问控制（🔴 严重）

**2026补充：** SSRF防护在云原生环境下更关键；AI Agent 工具调用授权须独立于模型推理；微服务东西向流量需独立访问控制。

**修复：** 服务端默认拒绝 + 统一访问控制框架（Casbin/OPA）+ SSRF白名单+阻私网 + API双鉴权（网关+业务层）。

**审计事项：** 检查所有API端点是否统一鉴权；测试IDOR越权；验证AI Agent工具最小权限。

#### A02 — 安全配置错误（🔴 严重）

**2026补充：** IaC模板配置审计；云安全配置（S3公开桶/KMS权限过度）；AI/LLM System Prompt配置泄露。

**修复：** CIS Benchmark + 修改默认凭据 + IaC安全扫描（tfsec/Checkov）+ HTTP安全标头完整部署。

#### A03 — 软件供应链失效（🔴 严重）🆕

**2026补充：** **AI供应链**成为新攻击面（预训练模型权重/LoRA适配器/MCP服务器插件）；SBOM已成为合规要求；依赖混淆攻击持续高发；模型序列化攻击（Pickle反向Shell）。

**修复：** SBOM + SCA自动化（Dependabot/Snyk/Trivy）+ 依赖固定版本+哈希校验 + 镜像扫描+签名 + **AI模型权重使用Safetensors替代Pickle** + AI SBOM。

#### A04 — 密码学失效（🔴 严重）

**2026补充：** **等国密强制**：GA/T 2380-2026要求三级系统强制SM2/SM3/SM4；密钥独立管理成为合规红线；量子计算抗性密码学进入规划。

**修复：** 强哈希（bcrypt/Argon2）+ TLS 1.2+强制 + KMS/HSM + 列级加密+动态脱敏 + **三级系统强制国密**。

#### A05 — 注入（🔴 严重）

**2026补充：** **AI Prompt注入**成为新注入大类（LLM01）；多模态注入（图像/PDF/音频中的恶意指令）。

**修复：** 参数化查询 + 白名单输入校验 + 输出编码Context-aware + WAF+RASP + **LLM输出视为不可信输入**。

#### A06 — 不安全设计（🟠 高）

**2026补充：** AI Agent设计的威胁建模成为必需；过度代理风险分类。

**修复：** STRIDE/PASTA威胁建模 + 速率限制/熔断 + AI Agent功能最小化（最小足迹原则）。

#### A07 — 身份验证失效（🟠 高）

**2026补充：** MFA已从建议变为基本要求；AI Agent身份继承与提权风险。

**修复：** MFA + 长密码策略 + Session安全（HttpOnly/Secure/SameSite）+ 登录限流+异常检测。

#### A08 — 软件或数据完整性失效（🟠 高）

**2026补充：** 自动更新通道签名验证；CDN子资源完整性SRI；AI Agent工具响应完整性校验。

**修复：** 软件更新签名验证 + SRI完整性校验 + 反序列化防护（类型白名单）+ JWT算法强制校验。

#### A09 — 安全日志与告警失效（🟡 中）

**2026补充：** **等保新规要求日志留存大幅延长**：普通≥1年，数据共享/跨境≥3年；日志WORM防篡改；AI Agent工具调用全程留痕。

**修复：** SIEM集中管理 + 实时告警+降噪 + WORM存储 + **日志留存策略对齐等保2026新规** + UEBA异常检测。

#### A10 — 异常处理失当（🟡 中）🆕

**修复：** 全局异常处理框架 + 分层错误信息（用户层不暴露技术细节）+ Fail Secure + try-with-resources + AI Agent异常兜底策略。

| LLM10 | Model Theft | **Misinformation** | 🔄 **重构** |

### 十大风险详解

#### LLM01 — Prompt Injection（🔴 严重）

**2026新增攻击面：** 多模态间接注入（图片白底白字指令/PDF元数据注入/音频隐写）；多Agent注入；记忆持久化注入。

**防护：** 假设模型终将服从恶意指令，设计爆炸半径最小化；不给聊天机器人不可容忍的误操作能力；按信任层隔离工具；不可逆操作需人工审批；结构化标记不受信内容；监控异常工具调用。

#### LLM02 — 不安全输出处理（🔴 严重）

**2026更新：** Agent动作输出——LLM决定调用的工具和参数即"输出"到达危险接收端；生成SQL/shell命令/文件路径时尤为危险。

**防护：** LLM输出视为不可信输入；使用结构化输出（JSON/Tool Calls）；渲染前HTML/Markdown净化；禁止自动加载远程图片；Agent动作参数化约束。

#### LLM03 — 训练数据投毒（🟠 高）

**2026扩展：** 微调攻击（LoRA适配器投毒）；RLHF偏好操纵；RAG索引语料投毒。

**防护：** 训练数据信任边界+过滤去重抽查；微调用保留对抗集评估；文档来源追踪+完整性校验。

#### LLM04 — 模型拒绝服务（🟡 中）

**2026新增：** 令牌放大攻击；递归扩展攻击（工具调用几何级数生成子任务）。

**防护：** 输入/输出长度限制；工具调用次数限制；每用户/会话速率限制；成本硬顶+异常消耗监控。

#### LLM05 — 供应链漏洞（🔴 严重）⬆️

**2026重大扩展：** 模型序列化攻击（Pickle→**强制使用Safetensors**）；MCP服务器插件妥协；量化模型替换攻击；依赖混淆攻击。

**防护：** AI SBOM；激进固定依赖版本；模型权重哈希校验+Safetensors；偏好模型官方SDK；开放权重微调前对抗探针评估；运行时按最小特权隔离插件。

#### LLM06 — 敏感信息泄露（🔴 严重）

**2026扩展：** 记忆系统泄露（跨会话记忆串味）；嵌入反演（从Embedding重建训练文本）；RAG跨租户数据泄露。

**防护：** 检索层强制租户范围过滤；密钥走工具脚手架不进系统提示；日志写入时脱敏；嵌入向量不可跨租户共享。

#### LLM07 — 过度代理（🔴 严重）🔄

**2026重构：** 提出"最小足迹原则"——最小权限、最小工具、最小能力范围；注入是触发，过度代理是爆炸半径。

**防护：** 每工具注册最窄范围和权限；写操作几乎总是需要人工确认；身份授权在模型外确定性代码判断；工具调用频率限制；定期审计Agent工具权限。

#### LLM08 — 无界消耗（🟡 中）🔄

**2026扩展：** 财务拒绝服务（Financial DoS）——不崩溃但产生高额成本。

**防护：** 每用户/会话速率限制；成本硬顶配置；输入/输出长度帽；工具调用次数上限；异常消耗实时告警。

#### LLM09 — 向量与嵌入弱点（🟠 高）🆕

**2026新增：** 嵌入反演；语义后门；检索绕过；跨租户数据泄露。

**防护：** 向量DB授权同主数据库（租户集合/库级过滤）；入索引文档内容安全校验；嵌入向量不可跨租户外享；定期渗透测试RAG隔离机制。

#### LLM10 — 错误信息（🟡 中）🔄

**防护：** Agent执行动作前独立验证；高危域人工确认；RAG+引用溯源；置信度阈值过滤。

## 六、GA/T 2380-2026 等保数据安全新规

### 核心变革：等保进入「双核合规时代」

> ⚠️ **旧模式**：网络+主机+防火墙过关即可通过等保，数据安全仅为附加项
> ✅ **新模式**：系统安全 + 数据安全**双独立考核**，数据安全单独打分
> **关键红线：33项重大风险点，触发直接一票否决！**

### 标准框架：1主线+3支柱+4级防护

**一条主线：数据8大生命周期全覆盖**
```
收集 → 存储 → 使用 → 加工 → 传输 → 提供 → 公开 → 销毁
```

**三大支撑体系：**
| 体系 | 内容 |
|------|------|
| 🛡️ 技术防护 | 数据分级标记、细粒度权限、国密加密、动态脱敏、数据库审计、内网微隔离、数据溯源、容灾备份 |
| 📋 管理保障 | 专职数据岗位、权责划分、制度台账、人员管控、供应链外包风控、审批流程标准化 |
| 🔍 审计监督 | 操作日志防篡改、超长留存、风险研判、泄露应急、全链路责任追溯 |

### 三级系统硬核强制条款（无缓冲、无豁免）

| 要求项 | 具体规定 |
|--------|---------|
| **国密加密** | 重要/敏感数据存储+传输**强制国密** SM2/SM3/SM4，淘汰单纯HTTPS |
| **存储隔离** | 核心/重要/一般数据逻辑/物理隔离，异地加密备份（同城≥30km、跨市≥100km） |
| **环境管控** | 测试/开发/报表环境禁止裸敏感数据，批量导出多级审批+强制脱敏 |
| **日志留存** | 普通日志≥1年，数据共享/跨境/委托处理日志≥3年，WORM防篡改 |
| **DBA审计** | 运维DBA操作全程留痕，独立审计权限 |
| **资产可视化** | 数据资产地图、数据血缘流向图，实时监测异常流转 |
| **跨境风控** | 重要数据出境前置安全评估，本地留存数据副本 |
| **AI/Agent** | 生成式AI、智能Agent正式纳入等保专项测评，日志留存≥180天 |

### 8大生命周期高频扣分红线

1. **数据收集**：禁止超范围采集；敏感个人信息禁止捆绑同意；数据源头绑定不可篡改安全标签
2. **数据存储**：三级及以上敏感字段禁止明文存储；不同级别数据禁止混存；备份数据同步加密
3. **数据使用加工**：测试环境零裸数据；U盘拷贝/外网传输/批量导库未经多级审批禁止
4. **数据传输**：禁止敏感数据明文内网传输；跨机构共享链路未加密留痕禁止
5. **第三方共享**：合作方资质未审核禁止；数据二次转包禁止
6. **数据公开**：重要/核心数据禁止对外公开
7. **数据销毁**：简单删除清空不可接受；电子数据覆写销毁；四级强制物理粉碎
8. **安全数据处理**（新增）：区分可逆去标识与不可逆匿名化

## 十、核心审计原则

1. **最小权限原则**：Agent工具和数据访问范围最小化
2. **信任分层**：用户输入≠检索文档≠工具响应，区分处理
3. **LLM输出不可信**：同用户输入安全纪律对待
4. **持续监控**：工具调用模式异常检测+成本异常告警
5. **人工参与**：不可逆操作必须人工确认
6. **假设已被攻破**：设计爆炸半径最小化，防御纵深
7. **安全左移**：需求设计→威胁建模→开发安全→自动化测试→运行时监控
8. **双核合规**：系统安全+数据安全独立考核，缺一不可
