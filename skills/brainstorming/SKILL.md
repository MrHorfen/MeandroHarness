# 头脑风暴技能

在开发前强制对需求进行梳理与澄清，通过交互式对话逐步形成可执行的设计方案与需求文档。

## 何时触发

✅ **WHEN TO USE:**
- 用户需求模糊，不清楚具体要做什么
- 复杂任务开始前，需要先理清思路
- 用户说「帮我想想怎么做」、「有什么方案」、「给点建议」
- 用户说「帮我规划一下」、「设计一下方案」
- 涉及多个可选方案，需要对比选择
- 项目初期，需求需要细化
- 乐谱转码方案选择（Audiveris vs oemer）
- HyperFrames 视频风格/方案确认

❌ **WHEN NOT TO USE:**
- 需求明确，可以直接执行 → 直接干
- 纯编码任务 → 用 fullstack-code-developer
- 纯文档撰写 → 用 doc-coauthoring
- 用户只是问问题，不需要方案设计 → 直接回答
- 简单的小任务 → 直接做

⚠️ **EDGE CASES:**
- 用户说「帮我做个XX」但描述很简略 → 先用 brainstorming 澄清需求，再执行
- 用户说「有什么好的方案」→ brainstorming 出方案，用户选了之后再执行

## 核心职责

### 需求澄清
通过提问方式逐步明确：
- 项目目标和范围（做什么，不做什么）
- 核心功能需求
- 技术约束和限制
- 使用场景和目标用户
- 预期成果和验收标准
- 时间/资源限制

### 方案探索
提供多个可选方案（至少2个，推荐3个）：
- 分析每个方案的优劣
- 评估实现复杂度和工作量
- 考虑扩展性和维护性
- 提供技术选型建议
- 给出推荐方案及理由

### 交互式对话
- 逐步深入细节
- 确认关键决策
- 记录讨论结果
- 形成共识文档

## 常见澄清问题模板

### 通用项目
1. 目标是什么？（最终要交付什么）
2. 范围边界？（什么做，什么不做）
3. 优先级？（哪些是必须的，哪些是可选的）
4. 技术约束？（语言、框架、环境等）
5. 时间要求？（什么时候要）

### 乐谱转码
1. 什么乐器的谱子？（钢琴/交响乐/民乐...）
2. 大概多少页？
3. 谱子质量怎么样？（扫描版/原版PDF/照片）
4. 需要什么输出格式？（MusicXML/MIDI/...）
5. 准确率要求多高？

### HyperFrames 视频
1. 什么主题？
2. 大概多长时间？
3. 横版还是竖版？
4. 什么风格？（科技感/简约/活泼...）
5. 有没有配音？
6. 什么时候要？

## 输出格式

```
💡 方案设计
━━━━━━━━━━━━━━━━━━━━━━━━━━━
🎯 目标: [明确的目标]
📋 需求梳理:
   - 必须有: [核心需求]
   - 可以有: [次要需求]
   - 不需要: [排除项]

📐 可选方案:
   ┌────┬─────────────┬──────┬──────┐
   │ #  │ 方案         │ 优点  │ 缺点  │
   ├────┼─────────────┼──────┼──────┤
   │ A  │ [方案A]     │ ...  │ ...  │
   │ B  │ [方案B]     │ ...  │ ...  │
   │ C  │ [方案C]     │ ...  │ ...  │
   └────┴─────────────┴──────┴──────┘

⭐ 推荐方案: [方案名]
   理由: [为什么推荐这个]

📅 实施步骤:
   1. [第一步]
   2. [第二步]
   3. [第三步]
   ...

❓ 待确认:
   - [需要用户确认的问题]
━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 与其他 Skill 的配合

| 任务 | 串联方式 |
|------|---------|
| 需求澄清 → 编码执行 | brainstorming → fullstack-code-developer |
| 方案设计 → 文档输出 | brainstorming → doc-coauthoring |
| 视频策划 → 制作执行 | brainstorming → media-producer |
| 复杂任务 → 总控调度 | brainstorming → master-controller |
