# PDF 转 MusicXML 技能

使用 OMR（光学乐谱识别）技术将 PDF 乐谱转换为可编辑的 MusicXML 格式。

## 何时触发

✅ **WHEN TO USE:**
- 用户要「PDF 转谱」、「乐谱转码」、「PDF 转 MusicXML」
- 用户要「识别乐谱」、「数字化乐谱」、「谱子转电子版」
- 用户说「把这个谱子转成 MuseScore 能用的格式」
- 用户要将纸质/扫描版乐谱转为可编辑格式
- 用户提到 OMR、Audiveris、oemer 等关键词
- 用户要批量转换乐谱

❌ **WHEN NOT TO USE:**
- 只是查看或阅读乐谱 → 直接打开 PDF
- 只是提取乐谱文本 → 用 PDF 文本提取
- MIDI 转谱 → 用专门的 MIDI 工具

⚠️ **EDGE CASES:**
- 用户说「帮我处理这个谱子」→ 先确认：是转码（PDF→MusicXML）还是演奏评估
- 谱子质量差 → 先做 PDF 标准化预处理，再识别
- 合唱+钢琴混合谱 → 先切割提取钢琴部分，再识别

## 支持的乐谱类型

| 类型 | 支持度 | 说明 |
|------|-------|------|
| 钢琴谱（单行/大谱表） | ✅ 高 | 最稳定，识别准确率高 |
| 交响乐总谱（多声部） | ✅ 中 | 24+ 声部可识别，需后处理 |
| 民乐谱 | ✅ 中 | 简谱/五线谱混合需预处理 |
| 吉他谱（六线谱） | ⚠️ 低 | 支持有限 |
| 声乐谱（带歌词） | ✅ 中 | 歌词识别可能有误差 |
| 合唱谱（SATB） | ✅ 中 | 需后处理分声部 |

## 工作流程（五步）

### 第一步：信息收集
必须先收集以下信息（用户未提供则主动询问）：
- 曲目标题
- 作曲家
- 乐器类型（钢琴/吉他/小提琴等）
- 声部类型（单声部/双声部/多声部）
- 调号（如知道）
- 拍号（如知道）
- 小节数（如知道）

### 第二步：PDF 标准化预处理
目标：将 PDF 转换为符合 Audiveris 技术边界的标准输入

| 参数 | 标准要求 |
|------|----------|
| DPI | 300 DPI（推荐），范围 200-500 |
| 图像格式 | 灰度图像（禁止RGB彩色或纯黑白二值） |
| 最大像素数 | < 20,000,000（硬性限制） |
| 谱线间距 | ~20 像素 |
| 歪斜 | 自动检测并校正（-5°到+5°） |

**预处理步骤：**
1. 渲染 PDF 为灰度图像（300 DPI）
2. 尺寸标准化（超过2000万像素则等比缩小）
3. 歪斜检测与校正
4. 温和图像增强（对比度1.2、轻微去噪、非锐化掩模）
5. 质量验证

### 第三步：OMR 识别
- 引擎：Audiveris（传统CV）或 oemer（深度学习，GPU加速）
- 逐页识别
- 输出：.mxl 压缩包 → 提取 XML

### 第四步：后处理
- 合并多页结果到一个 MusicXML 文件
- 修正识别错误（调号、拍号、音符时值等）
- 声部对齐与合并

### 第五步：输出与校验
- 检查 Part 数量（钢琴谱 1-2 个）
- 检查总小节数是否合理
- 检查文件大小（正常 >100KB）
- 生成转换报告

## PDF 独立性原则（铁律）

每份 PDF 必须独立冷启动处理：
- ❌ 禁止复用之前 PDF 的页数、乐器类型、声部信息
- ✅ 每次必须自动检测总页数
- ✅ 每次必须重新分析乐谱属性
- ❌ 禁止硬编码 `page_range=[0,1,2]`
- ✅ 输出文件必须独立命名

## 钢琴+合唱混合谱处理方案

如果需要提取钢琴部分、去除人声声部：

1. **分析页面布局**：定位 "Pno."、"S."、"A."、"T."、"B." 等标识的 Y 坐标
2. **确定切割范围**：第一页布局通常不同，需单独处理
3. **执行切割**：用白色矩形遮盖非钢琴区域，创建新 PDF
4. **验证结果**：确认钢琴部分完整，人声声部已清除

## 输出验证清单

- [ ] MusicXML 格式正确，可被 MuseScore/Sibelius 打开
- [ ] Part 数量符合乐器类型
- [ ] 调号、拍号正确
- [ ] 总小节数在合理范围
- [ ] 文件大小正常（>100KB）
- [ ] 文件名包含曲名，独立不重复
- [ ] 生成了转换报告
